# Device Workshop

Сайт мастерской Тиграна и Telegram Mini App: адаптивная вёрстка, анимации, услуги и цены, отзывы, статьи, контакты и подготовка сообщения в Telegram. Статический HTML/CSS/JS без сборки, базы заявок и зависимостей. Бот на Python запускается отдельно.

## Сайт и Mini App

```sh
cd /workspace/TigranSite
python3 -m http.server 8080 --bind 0.0.0.0
```

Главная — `index.html`, Mini App — `miniapp.html`. Все пути относительные: приложение поддерживает подкаталог GitHub Pages. Каталог Mini App и бота — `data/services.json`. На основной странице цены находятся в `index.html`; при обновлении меняйте оба источника. Формы открывают `@DeviceWorkshop` с подготовленным текстом; клиент сам отправляет его в Telegram. Есть резервное копирование текста, если переход в чат не сработал. Сообщения не сохраняются на сайте.

## Публикация на GitHub Pages

В репозитории откройте **Settings → Pages → Source → GitHub Actions**. Push в `main` запускает `.github/workflows/pages.yml`. В артефакт попадают только публичные файлы; Python, тесты, переменные окружения и документация не публикуются. GitHub Pages не исполняет Python-бота.

После успешного развёртывания адрес Mini App будет: `https://trofimmokrov-netizen.github.io/TigranSite/miniapp.html` (если используются стандартные настройки Pages без собственного домена). Само наличие workflow ещё не означает, что Pages включён и адрес доступен.

## Запуск Telegram-бота

**Самый простой постоянный вариант без VPS:** [docs/START-BOT.md](docs/START-BOT.md). Готовый файл для публикации — [deploy/worker.mjs](deploy/worker.mjs). Сайт остаётся на GitHub Pages; команды обслуживаются Cloudflare Worker. Инструкция ниже описывает альтернативный запуск на компьютере.

Нужен Python 3.10+, сторонние пакеты не требуются. Бот может работать на вашем компьютере, пока тот включён. Для круглосуточной работы позже можно перенести его на сервер. Публичный IP компьютера не нужен: используется long polling.

1. Перевыпустите опубликованный в переписке токен через BotFather.
2. Передайте новый токен только через переменную окружения `TELEGRAM_BOT_TOKEN`. Не помещайте его в код или GitHub Pages. `.env.example` содержит только названия настроек и не загружается автоматически.
3. Установите `PUBLIC_URL` равным адресу опубликованного сайта **без завершающего слеша**, например `https://trofimmokrov-netizen.github.io/TigranSite`.
4. Выполните `python3 backend/bot.py` из корня проекта. Запускайте один экземпляр бота. Если ранее настроен webhook, его нужно предварительно отключить: long polling с ним несовместим. Существующий webhook код автоматически не удаляет.

При старте бот проверяет токен через `getMe`, регистрирует команды и настраивает кнопку меню Mini App. Команды: `/start`, `/repair`, `/prices`, `/print`, `/contacts`, `/hours`, `/site`, `/help`. Кнопки открывают услуги, контакты, карту и чат мастера. Обычные сообщения не пересылаются мастеру; бот явно сообщает об этом клиенту. Бот не хранит переписку в базе.

### Название, описание и меню

Публичные тексты профиля находятся в `backend/bot_settings.py`. Для разовой настройки выполните `python3 backend/configure_bot.py`, для проверки без изменений — `python3 backend/configure_bot.py --check`. Скрипт устанавливает название, полное и короткое описание, восемь команд и кнопку Mini App, затем считывает настройки обратно. Устанавливаются русский и стандартный варианты. Нужны `TELEGRAM_BOT_TOKEN` и `PUBLIC_URL` в окружении.

Можно настроить профиль через GitHub: сохраните токен в **Settings → Secrets and variables → Actions → New repository secret** под именем `TELEGRAM_BOT_TOKEN`, затем запустите **Actions → Configure Telegram bot → Run workflow**. Токен не входит в сайт или репозиторий. Этот разовый workflow настраивает профиль, но не является постоянным процессом для ответов на команды.

### Фотографии

На главной странице добавлен раздел с прямым переходом в оригинальную фотогалерею мастерской на Яндекс Картах. Снимки не скопированы в репозиторий: получение галереи из текущей облачной среды блокируется сетевой политикой (403 прокси). Для локальной фотогалереи нужны доступ к источнику или предоставленные владельцем файлы; ссылки на несуществующие снимки и чужие фотографии не добавлялись.

Можно также вручную настроить кнопку меню через BotFather → `/mybots` → Bot Settings → Menu Button, указав HTTPS-адрес `miniapp.html`. Тогда переход в Mini App не требует работающего Python-процесса; ответы на команды требуют.

Постоянный webhook-вариант по архитектуре проекта Ксюши подготовлен в `backend/webhook.mjs`. Сравнение проектов, настройки и оставшийся этап публикации описаны в [docs/telegram-hosting.md](docs/telegram-hosting.md). Публичный сервис в этой задаче пока не развёрнут. После обновления файлов конфигурации в `main` настройка профиля бота запускается автоматически через GitHub Actions с уже добавленным repository secret.

## Проверки

```sh
node --check app.js
node --check miniapp.js
python3 -m unittest discover -s backend -v
```

Браузерная проверка: `python3 tests/browser_smoke.py` при запущенном сайте. Для неё нужны Playwright и Chromium; они не являются зависимостями сайта. Проверяются мобильное меню, цены, форма сообщения, ссылка Telegram, Mini App, отсутствие горизонтальной прокрутки и страницы статей.

## Данные и оформление

### Актуальное обновление сайта

Главная содержит отдельный блок работающего бота [@DeviceWorkshop_bot](https://t.me/DeviceWorkshop_bot), а связь с мастером ведёт в отдельный чат [@DeviceWorkshop](https://t.me/DeviceWorkshop). Галерея показывает два снимка мастерской и шесть рекламных материалов из предоставленного архива; есть просмотр в диалоге, клавиши стрелок, Escape и ссылка на оригинал. Происхождение файлов: `assets/workshop/SOURCES.md`.

В журнале восемь статей, иллюстрации — локальные SVG в `assets/journal`. Скрипт `motion.js` добавляет плавные появления, прогресс чтения, подсветку навигации и кнопку наверх. Контент остаётся видимым при отключённом JS, а `prefers-reduced-motion` отключает анимации. Новые стили — `presentation.css`.

Локальный поиск: canonical, Open Graph / Twitter, регион RU-MOW и адрес, JSON-LD LocalBusiness с услугами и графиком, структурированный журнал и sitemap.xml. Непроверенные координаты и обещания рейтинга в поиске не добавлены. `robots.txt` пригоден при размещении в корне собственного домена; для project GitHub Pages действуют meta robots страниц и sitemap, а управление корневым robots.txt принадлежит владельцу домена github.io. При подключении собственного домена обновите абсолютные URL в метаданных и sitemap.

Дополнительная браузерная проверка: `python3 tests/presentation_smoke.py` при запущенном статическом сервере и установленном Playwright/Chromium. Она проверяет реальные ссылки бота, галерею, мобильную навигацию после прокрутки, иллюстрации, JSON-LD и уменьшение анимаций.

Цены и фрагменты отзывов — из предоставленной карточки Яндекс Карт; актуальную стоимость согласует мастер. Карта на сайте декоративная, кнопка открывает настоящий маршрут.

Политика данных и описание localStorage — `privacy.html`. Нет аналитики, рекламы и cookies приложения. Сохраняется только факт закрытия уведомления. Шрифт хранится локально с лицензией. Поддерживаются клавиатура и уменьшение анимаций по настройкам устройства.

### Логотип и удобство чтения

Шапка и подвал используют присланный знак (яблоко с Android) и название Device Workshop с заглавных букв. Прозрачная версия — `assets/brand/logo.png`. Дополнительная карточка контактов воспроизведена доступным HTML с кликабельными телефоном и адресом. Файл `readability.css` увеличивает основной текст до 18 px, вторичный до 14–16 px и усиливает контраст. Кнопки «Текст крупнее» и «Пауза анимаций» доступны на всех четырёх страницах. Размер текста увеличивается до 21 px, выбор сохраняется локально. Системный `prefers-reduced-motion` имеет приоритет. Проверка: `python3 tests/readability_smoke.py`.

### Стиль текстов

Использовать сдержанный деловой стиль: конкретные услуги, порядок ремонта, стоимость и контакты. Не добавлять разговорные слоганы, шутки и эмоциональные обращения. Цитаты клиентских отзывов сохранять без редакторских изменений.
